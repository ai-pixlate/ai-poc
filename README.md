### 구현 시 유의

- **원문 지우기 신뢰도 하한은 파라미터로 둘 것**(기본 0.5). `erase_all` ↔ `erase_s50` 차이가 마스크 필터 한 줄임
- **좌표는 섹션 로컬로 다루고 원본 위치는 `top_offset + y`로 복원할 것.** 페이지 좌표로 섞으면 ①의 분할·검산이 깨짐
- **번역문은 조판으로 흡수되지 않음**(초과율 97%) — 길이 압축이나 레이아웃 재설계, 또는 **검수 단계를 전제로 설계할 것**
- **`role` 5종에 제품명 유형이 없음** — 번역에서 `미백 앰플` 같은 제품명/효능 주장 구분 문제가 남음
- 심볼형 로고(글자 아닌 로고)는 **텍스트 대조로 못 잡음** — 표본이 전부 워드마크라 미검증

## 1. 텍스트 추출 — **확정**

### 결과

| 항목 | 결정 |
|---|---|
| 엔진 | **PaddleOCR** |
| 모델 | `PP-OCRv5_server_det` + `korean_PP-OCRv5_mobile_rec` |
| 전처리 | **적용 안 함** |

| variant | 판정 | 사유 |
|---|---|---|
| `baseline` | **채택** | 육안 대부분 A. 70% 게이트 통과 |
| `det_side_1280` | 제외 | 12장 전부 baseline과 **인식 결과 완전 동일** |
| `vl_spotting` (PaddleOCR-VL) | 제외 | 12장 1,042초 — baseline의 **약 300배** |

### 검증 방법

이미지 12장 · **이미지 단위** A/B/C 육안 판정. 단계적 게이트 — A+B 70% 이상이면 다음 단계 생략.

### 과정

baseline이 게이트를 통과해 전처리 단계로 넘어가지 않음. 한국어 인식 모델 상향을 시도했으나 **server 등급 인식 모델은 전부 중국어·영어·일본어용**이고 한국어는 `mobile`뿐이라 구조적으로 불가함을 실측으로 확인함.

**골든 재실행(2026-09-16)** — 섹션 102개 전수 판정으로 **텍스트 98% · bbox 99%**. 사진·그라데이션 배경 위 글자 39섹션은 전부 A+B. **4,000px 초과 섹션은 OCR 전에 한 번 더 자르는 규칙**을 적용함(여백 우선 · 없으면 2,000px 띠 300px 겹침) — 안 자르면 검출기가 축소해 참조 일치율이 91.9%에 그침.

저신뢰·빈 텍스트 영역 111개(4.9%)를 전수 분류함 — **실제 글자 90**(표 잔글씨·제품 인쇄·캡처 문서), **글자 아님 21**(얼굴·물방울·아이콘). **빈 텍스트를 "글자 아님"으로 읽으면 안 됨** — 빈 텍스트 40개 중 28개가 실제 글자임.

> ⚠️ **12장 표본의 개별 등급은 기록되지 않음.** `poc/B_ocr/summary.md` 판정표 12행이 빈 칸이며 근거는 총평뿐임. **기준선은 골든 재실행분이 유일함.**

### 지우는 영역 — `erase_s50`으로 변경 (2026-09-16)

| 조건 | 골든 102섹션 | 사진 위 글자 | 글자 아닌 영역을 지움 |
|---|---|---|---|
| `erase_all` 모든 OCR 영역 (기존) | 66% | 54% | **15영역 · 9섹션** |
| **`erase_s50`** 신뢰도 0.5 이상 · 텍스트 있는 영역 | **72%** | **71%** | **0** |

**모든 OCR 박스를 지우면 얼굴·신체·물방울·아이콘이 함께 지워짐.** 신뢰도 하한 하나로 전부 막힘. 맞교환은 판독 불가 잔글씨 54개가 원문에 남는 것 — 어차피 번역 대상에서 빠지는 글자임.

- 구현 시 **하한은 파라미터로 둘 것**(기본 0.5). 두 조건의 코드 차이는 마스크 필터 한 줄임
- **마스크 면적으로 실패를 예측할 수 없음** — 골든 등급별 마스크 비율 중앙값이 A 18.0% · B 17.0% · C 17.2%로 갈리지 않음. 12장에서 나온 "면적 최대 2장이 C"는 재현되지 않음

### 검증 방법

표본 12장 · A/B/C 육안 판정. 마스크는 텍스트 추출의 bbox를 **글자 높이 15% 팽창**. 제품 인쇄 글자는 판정에서 제외.

### 과정

SD 계열은 설정 3축(guidance·steps·네거티브)을 바꿔도 **지운 자리에 가짜 글자·라벨을 생성함**. 결정적으로 LaMa가 A를 받은 쉬운 이미지에 적용했더니 **멀쩡한 부분까지 가짜 무늬로 채움**.

> **구조적 원인** — SD는 마스크 주변을 보고 채울 내용을 **생성함**. 상세페이지는 주변이 온통 글자라 "여기도 글자"가 가장 그럴듯한 답이 됨. LaMa는 주변 화소를 확장·복원해 실패해도 흐려질 뿐 **없던 것이 생기지 않음.**

LaMa가 C를 받은 2장은 마스크 면적 1·2위(47%·32%)로, **기술 한계가 아니라 마스크 과대**가 원인임.

| **의미 섹션** | 하류(조판·검수)가 쓰는 문맥 단위 |

## 10. 브랜드 로고 제외 — **확정**

### 결과

| 항목 | 결정 |
|---|---|
| 채택 | **`block_exact`** — 줄·문단 병합 블록의 **텍스트 전체가 브랜드명과 같으면** 제외 |
| 위치 | 줄·문단 병합 → 제품 라벨 판정 → **로고 제외(문자열 후처리)** |
| 입력 | 블록 텍스트 + 상품 브랜드명 사전(영·한 표기) |
| 정규화 | NFKC · 소문자 · 공백·문장부호 제거 (`b.clinicx` → `bclinicx`) |
| 비용 | **0** — OCR·병합이 파이프라인 공통 단계라 대조만 추가 |

| 대조 단위 | 찾음 | 놓침 | 오탐 |
|---|---|---|---|
| `block_exact` · `heuristic_v2` 블록 | 6 | 1 | **0** |
| `block_exact` · `llm_assist` 블록 (골든 재실행) | 5 | **2** | **0** |
| `region_exact` · OCR 영역 (대안 측정) | 6 | 1 | **5** |

**`block_exact` 유지로 종결.** 놓침 2 · 오탐 0을 수용함.

### 검증 방법

골든 34장 전수 · 페이지 로고 7개와 **기계 대조**(IoU ≥ 0.5). 사람이 채울 칸 없음. 종결 기준은 놓침·오탐이 기존보다 늘지 않는 것.

### 과정

**템플릿 매칭으로 착수했다가 방식을 바꿈.** 페이지 로고 주변을 OCR로 읽어보니 **전부 글자로 읽힘**(신뢰도 0.93~1.00) — 표본 로고가 전부 워드마크라 OCR 영역에 이미 들어 있었음. 템플릿은 로고 파일이 필요하고 34장 최대 348초로 무거워 탈락.

**놓침·오탐은 맞교환임.** 대조 단위를 키우면 로고가 옆 글자와 묶여 놓치고, 줄이면 제목 첫 줄이 브랜드명인 블록에서 오탐이 남(`비클리닉스 / 브라이트닝 세럼`). **오탐은 제목이 반쪽만 번역되게 만들어 더 나쁨.**

- 놓친 `Good all goodal`은 **OCR이 애초에 한 영역으로 읽음** — 대조 단위를 바꿔도 못 잡음
- 놓친 `celimax× OLIVE YOUNG`은 콜라보 로고 2개가 한 줄에 붙은 유형임
- **심볼형 로고는 미검증** — 표본이 전부 워드마크임. 글자가 아닌 로고는 텍스트 대조로 못 잡음

> 로고 제외는 병합 블록에 얹은 문자열 규칙이라 **병합 조건을 바꾸면 놓침 수가 함께 바뀜.** 병합을 손보면 대조를 다시 돌릴 것 — `python poc/logo_match/run_text.py --sample golden --unit all`, 비용 0.
